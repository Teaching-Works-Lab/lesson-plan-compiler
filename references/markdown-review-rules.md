# 教案 Markdown 与审查规则

## 工作文档合同

工作 Markdown 为 AI 审查与内容协作优化，不模仿 Word 版式。它保留：

- YAML 控制字段（版本、文档状态、课程名、学年学期）；
- 来源与证据边界放在正式内容之外（`# 编制信息` / `# 内部追踪区`）；
- 一个字段—值表承载课程事实；
- 每个教学单元一个稳定的 `lesson-XX` 标识，教学目标、课程思政等长文本用 `####` 小节承载，教学过程用固定三列表格；
- 来源状态、缺项与冲突只在追踪区出现，不进入正式内容。

正式 Word 只包含 `official`、`provided` 与已确认的 `derived` 内容；不得包含 `reference_only`、未解决的 `to_confirm`、来源状态标签、内部审查意见或变更建议。

## 教学过程单元格的多行写法

`主要教学内容` 单元格内，用 `<br>` 表示换行，把「【教师】」「【学生】」「【要求】」各块与编号条目分行。渲染到 Word 时 `<br>` 转为单元格内换行。示例：

```markdown
| 课前任务 | 【教师】1. 发布预习任务，明确教材对应内容；<br>2. 提醒学生围绕[……主线]思考关键步骤。<br>【学生】1. 阅读教材并梳理疑问；<br>2. 带着问题进入课堂。 | 通过课前预习让学生初步建立认知，同时培养信息收集能力。 |
```

## 审查级别

- `basic`：客观的正式交付门禁——必填字段、课时、七步教学过程完整性、稳定标识、未解决占位符。
- `changed`：复用未变化的构建签名；内容变化后重跑廉价客观门禁，并将额外审查限制在受影响小节及其下游关系。
- `enhanced`：用于新模板或新环境、不可靠抽取、官方来源冲突、批量生成、重大结构改动、`basic` 未通过或明确的全面审查请求。

只断言客观值。教学适配性、措辞、难度、真实性、思政融合、单元命名等是带证据的警告或决定；警告不因请求了 `enhanced` 审查而自动升级为阻断项。

## 停止条件

输入、规则、脚本、配置与环境签名均未变化时，不重复执行等价检查。请求的产物通过其适用门禁与受影响范围审查后即停止。仅为模板、仅分析、仅审查的请求不生成 Word。
